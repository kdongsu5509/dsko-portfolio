## 문제

- AI 에이전트가 다른 모듈의 내부 클래스와 JPA 엔티티를 직접 참조하는 코드를 계속 만듦
- 한 곳을 고치면 다른 도메인까지 깨지는데 어디까지 번지는지 코드만으로는 알 수 없음
- Spring Modulith 경계 검사를 켜자 공개하지 않은 타입 참조 224건과 순환 의존 7건이 나옴

## 해결

- 검사를 바로 강제하면 모든 빌드가 깨지므로 경계 검사 테스트는 잠시 끄고 남은 위반 목록을 테스트 코드에 적어 둠
- 여러 모듈이 함께 쓰는 타입은 공개 인터페이스로 옮기며 커밋을 나눠 위반을 줄임. 인증 사용자 정보 하나만 옮겨도 84건이 사라짐
- 이벤트 뒤에 숨은 의존은 명시적인 호출로 바꿔 의존 방향이 생성자에 드러나게 함. 마지막 2건을 지운 뒤 경계 검사를 켜고 배포 파이프라인 테스트 단계에 넣음

## 결과

- 공개하지 않은 타입 참조 224건과 순환 의존 7건을 모두 0건으로 줄임
- 이후 main에 들어온 경계 위반 2건이 배포 전에 멈춤. 그중 하나는 탈퇴 API에 인증 모듈 애노테이션을 붙여 생긴 인증과 회원 사이 순환이었고 애노테이션을 공용 모듈로 옮겨 순환을 끊음
- 정리하는 동안 기존 테스트 686개는 모두 통과함

## 한계

- 혼자 개발하며 main에 바로 올린 변경은 PR 검사를 거치지 않아 위반을 배포 단계에서야 발견함. 경계 검사를 커밋 전 단계로 앞당겨야 함
- 경계 검사는 모듈 사이 참조만 봄. 모듈 안에서 책임을 어디에 둘지는 여전히 사람이 판단함
