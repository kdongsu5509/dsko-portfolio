### 문제

- 인사나 용어 설명 같은 간단한 질문에도 복잡한 질문과 같은 요금과 같은 대기 시간이 듦
- 프롬프트를 보강하자 평가 57개를 돌리는 시간이 18분 38초에서 26분 57초로 늘고 비용도 함께 커짐

### 원인

- 모든 질문을 상위 모델 Sol 하나로 처리함
- 프롬프트 주입과 도메인 밖 요청도 걸러야 하는데 검사마다 모델을 따로 부르면 호출이 그만큼 늘어나는 구조였음

### 고려한 방법

- **상위 모델 하나를 유지**: 품질은 가장 안정적이지만 비용과 대기 시간이 그대로임
- **난이도 분류와 주입·이탈 검사를 각각 호출**: 판단은 나뉘어 명확하지만 질문마다 모델 호출이 세 번 늘어남
- **분류 모델 한 번에 세 가지를 함께 판정하고 결과에 따라 모델을 나눔**: 호출을 한 번으로 줄이면서 간단한 질문은 싼 모델로 보낼 수 있음
- 실패 처리도 **항상 다음 모델로 재시도**, **재시도 없음**, **안전할 때만 재시도** 중에서 골라야 했음

### 선택과 이유

- **분류 모델 Jev 한 번에 난이도, 프롬프트 주입, 도메인 이탈을 함께 물음.** 주입이나 이탈이면 답변 모델을 부르지 않고 차단함
- 난이도에 따라 LOW는 Qwen, MEDIUM은 Luna, HIGH는 Sol로 보냄. 일정과 체크리스트 변경은 모델이 서버 기능을 직접 호출하는 Tool Calling으로 처리함
- **분류가 실패하면 비용보다 품질을 택해 HIGH로 보냄.**
- **재시도는 안전할 때만 함.** 사용자에게 글자를 이미 보냈다면 답변이 섞이고 일정이나 체크리스트를 바꾸는 도구를 이미 불렀다면 같은 변경이 두 번 일어나므로 이때는 재시도하지 않음

### 감수한 것

- 분류가 틀리거나 실패한 질문은 비싼 모델로 처리됨
- 글자를 이미 보냈거나 쓰기 도구를 불렀다면 재시도하지 않으므로 이때는 사용자가 실패를 그대로 보게 됨
- 간단한 질문은 평균 0.88초로 빨라졌지만 전체 평균 첫 응답은 3.24초에서 3.20초로 거의 그대로임
- 효과를 작은 표본으로 확인함. 변경 전 42턴과 변경 후 운영 요청 94건(팀 테스트 섞임)을 비교했고 Tool Calling 포함 여부도 조금 다름

### 결과

- 같은 요청을 Sol로만 처리할 때보다 예상 비용이 절반 수준으로 낮아짐
- 같은 평가를 다시 돌린 실제 비용은 0.74달러에서 0.57달러로 23% 줄어듦
- 악성 질문 테스트 10건을 모두 차단함

### 다시 한다면

- 응답 시간 목표를 모든 요청에 하나로 잡지 않고 난이도별로 따로 잡음
- 비교 표본을 더 늘리고 Tool Calling 포함 여부 같은 조건을 맞춰 효과를 다시 확인함
