### 문제

사용자가 챗봇으로 더 다양한 일을 처리할 수 있도록 Tool Calling을 도입하고 시스템 프롬프트를 더 자세히 바꿨습니다. 답변 품질은 기존에 쓰던 LLM as a Judge 평가로 쟀습니다. 평가 전용 모델이 시나리오 57개를 8개 지표로 채점하는 방식입니다. 같은 평가를 다시 돌렸더니, 프롬프트를 보강해 목표 미달이 12건에서 6건으로 줄었지만 입력 토큰이 23.6% 늘고 같은 평가를 돌리는 시간이 18분 38초에서 26분 57초로 늘어났습니다. 평가에서 확인한 추정이지만 실제 응답 시간도 길어질 것으로 보였습니다.

### 원인

Tool Calling과 상세한 프롬프트로 모델이 처리할 입력이 커졌는데, 모든 질문을 상위 모델 Sol 하나로 처리했습니다. 그래서 인사나 용어 설명 같은 간단한 질문도 복잡한 질문과 같은 대기 시간과 비용이 들었습니다.
### 고려한 방법

질문을 분류해 난이도별로 모델을 나누는 것은 정해져 있었고, 분류를 맡길 모델을 골라야 했습니다.

- **AWS 분류 모델**: 지금 서버가 OpenAI 모델을 직접 호출하는 방식이라 붙일 수 없고, AWS 모델 권한을 요청했지만 받지 못해 쓸 수 없었습니다.
- **OpenAI Luna**: 분류에도 쓸 수 있습니다. 입력 100만 토큰에 $0.10, 출력 100만 토큰에 $0.50이고 첫 토큰까지 걸리는 시간의 중앙값은 약 0.88초입니다([가격](https://anotherwrapper.com/llm-pricing/gpt-6-luna), [속도](https://pricepertoken.com/pricing-page/model/openai-gpt-6-luna)).
- **Jev**: 입력 100만 토큰에 $0.042이고 출력은 무료입니다. 단순한 분류 호출의 응답 시간 중앙값은 한 외부 측정에서 0.66초였습니다([가격](https://www.layer3labs.io/guides/jev-pricing), [속도](https://dev.classmethod.jp/en/articles/jev-for-llm-model-routing/)).

### 선택과 이유

**분류 모델로 Jev를 택했습니다.** AWS 분류 모델은 쓸 수 없었고, Jev와 Luna 중에서는 공개된 가격표와 측정값으로 비교했을 때 Jev가 호출 비용이 더 싸고 응답도 빨랐기 때문입니다.

**호출 수를 줄이려고 Jev 한 번에 난이도, 프롬프트 주입, 도메인 이탈을 함께 묻습니다.** 검사마다 모델을 따로 부르면 질문마다 호출이 그만큼 늘기 때문입니다. 주입이나 이탈이면 답변 모델을 부르지 않고 차단합니다. 난이도 기준은 OpenRouter와 각 모델의 판단 기준을 참고해 정했고, 난이도에 따라 LOW는 Qwen, MEDIUM은 Luna, HIGH는 Sol로 보냅니다. 일정과 체크리스트 변경은 모델이 서버 기능을 직접 호출하는 Tool Calling으로 처리합니다.

**분류가 실패하면 비용보다 품질을 택해 HIGH로 보냅니다.** Jev 호출이 실패하거나 API 키가 없을 때가 여기에 해당합니다. 호출은 성공했지만 분류의 확신도가 0.7보다 낮으면, 분류된 등급보다 한 단계 위 모델로 보냅니다.

**답변 모델 호출이 실패하면 안전할 때만 다른 모델로 재시도합니다.** 사용자에게 글자를 이미 보냈다면 답변이 섞이고, 일정이나 체크리스트를 바꾸는 도구를 이미 불렀다면 같은 변경이 두 번 일어나므로 이때는 재시도하지 않습니다. 재시도 순서는 LOW가 MEDIUM, HIGH, MEDIUM이 HIGH, LOW, HIGH가 MEDIUM, LOW입니다.

### 감수한 것

- 분류가 틀리거나 실패한 질문은 비싼 모델로 처리됩니다.
- 글자를 이미 보냈거나 쓰기 도구를 불렀다면 재시도하지 않으므로, 이때는 사용자가 실패를 그대로 보게 됩니다.
- 간단한 질문은 평균 0.88초로 빨라졌지만 전체 평균 첫 응답은 3.24초에서 3.20초로 거의 그대로입니다.
- 분기 후 품질은 같은 LLM as a Judge로 다시 재지 못했습니다. 평가가 CLI 모델 기준이라 운영 모델인 Bedrock에서의 품질은 확인하지 못했습니다.
- 효과를 작은 표본으로 확인했습니다. 변경 전 42턴과 변경 후 운영 요청 94건(팀 테스트 섞임)을 비교했고, Tool Calling 포함 여부도 조금 다릅니다.

### 결과

- 같은 요청을 Sol로만 처리할 때보다 예상 비용이 절반 수준으로 낮아졌습니다.
- 같은 평가를 다시 돌린 실제 비용은 0.74달러에서 0.57달러로 23% 줄어들었습니다.
- 악성 질문 테스트 10건을 모두 차단했습니다.

### 다시 한다면

- 응답 시간 목표를 모든 요청에 하나로 잡지 않고 난이도별로 따로 잡습니다.
- 분기 전후 답변을 같은 LLM as a Judge로 채점해, 비용을 줄인 만큼 품질이 얼마나 변했는지 확인합니다.
- 비교 표본을 더 늘리고 Tool Calling 포함 여부 같은 조건을 맞춰 효과를 다시 확인합니다.
