## 문제

- 문서와 skill에 팀 컨벤션을 적어 두었지만 AI가 만든 코드는 계층 방향과 클래스 이름, 위치 규칙을 계속 어김
- 리뷰어가 PR마다 같은 지적을 반복하느라 설계 논의가 뒤로 밀림
- 그 사이 기능 패키지끼리 서로 참조하는 순환과 다른 기능의 Repository를 직접 부르는 코드가 쌓임

## 해결

- 팀원 1명과 함께 컨벤션을 ArchUnit 규칙 13개로 옮김. 의존 방향 4개, 이름과 위치 5개, 작성 규칙 4개로 나눔
- 규칙을 PR CI의 gradlew check에 넣어 dev-be와 release-be로 가는 모든 PR에서 돌게 함
- 규칙을 켜며 드러난 순환 참조와 Repository 직접 호출은 같은 PR에서 각 기능의 Service를 거치도록 고침

## 결과

- 규칙에 담긴 지적은 리뷰어 대신 CI가 하고 위반 코드는 머지 전에 실패함
- 도입 PR에서 85개 파일을 고쳐 기능 패키지 사이 순환 참조를 없앰
- 이후 AI 챗봇을 붙이며 대화 서비스가 Spring AI 타입에 직접 의존하지 않는다는 규칙을 직접 추가함. 지금은 16개

## 한계

- 규칙은 이름, 위치, 의존 방향처럼 기계로 판단할 수 있는 것만 잡음. 책임을 어디에 둘지는 여전히 리뷰에서 정함
- 테스트가 통과해도 그 테스트가 무엇을 검증하는지는 알 수 없음. 코드를 일부러 바꿔 테스트가 잡아내는지 보는 PIT 변이 검사를 변경된 클래스에 붙였지만 아직 실제 PR에서 돌린 결과는 없음
