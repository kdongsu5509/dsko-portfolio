## 문제

- 문서와 skill에 팀 컨벤션을 기록해 두었지만 AI가 생성한 코드에서는 계층 방향이나 클래스 이름과 위치 규칙을 어기는 부분이 계속 나왔음
- 리뷰어가 PR마다 직접 확인하며 같은 지적을 반복했고 정작 설계에 대한 논의는 뒤로 밀렸음
- 그 사이 기능 패키지끼리 서로를 참조하는 순환과 다른 기능의 저장소를 직접 부르는 코드가 쌓였음

## 해결

- 팀원 1명과 함께 컨벤션을 ArchUnit 규칙 13개로 옮겼음. 계층 의존 방향과 기능 사이 순환 금지 같은 의존 방향 규칙, Service와 Repository 같은 이름과 위치 규칙, Lombok은 Slf4j만 허용하는 것 같은 작성 규칙으로 나눴음
- 규칙을 PR CI의 gradlew check에 넣어 dev-be와 release-be로 가는 모든 PR에서 돌게 했음
- 규칙을 켜면서 드러난 순환 참조와 다른 기능 저장소 직접 호출은 같은 PR에서 각 기능의 Service를 거치도록 고쳤음

## 결과

- 컨벤션을 어긴 코드는 머지 전에 CI에서 실패하게 되어 리뷰어가 같은 지적을 반복하지 않게 됐음
- 도입 과정에서 85개 파일을 고쳐 기능 패키지 사이 순환 참조를 없앴음
- 이후 AI 챗봇을 붙이면서 대화 서비스가 HTTP와 Spring AI 타입에 직접 의존하지 않는다는 규칙을 직접 추가하는 등 규칙이 기능과 함께 늘어 현재 16개

## 한계

- 규칙은 이름, 위치, 의존 방향처럼 기계적으로 판단할 수 있는 것만 잡음. 책임을 어디에 둘지 같은 판단은 여전히 리뷰 몫
- 테스트가 통과해도 그 테스트가 실제로 무언가를 검증하는지는 알 수 없음. 변경된 클래스에 PIT 변이 검사를 붙였지만 아직 실제 PR에서 돌린 결과는 없음
